# 15 常见进阶算法与大数据选型

这些主题用于核心手写题之后的拓展。本页提供原理、适用边界与练习入口，不把它们计入 36 道完整 Java 题解。

## Trie：按前缀组织，而不是只按完整键查询

Trie 每条边对应一个字符，沿根到节点的路径表示前缀，节点还需维护单词结束标记。已有路径不等于该前缀本身就是完整单词。例如插入 apple 后，前缀 app 存在，但 search(app) 应失败，除非另行插入 app。

固定字母表数组孩子访问可做到每字符 O(1)，查找长度 L 的单词为 O(L)。空间要计入实际节点数与每节点孩子表；稀疏字母表可用映射以减少大量空指针。删除时需要保证共享前缀仍被其他词使用。练习 [LC 208](https://leetcode.com/problems/implement-trie-prefix-tree/)。

## KMP：复用已经匹配过的前后缀

KMP 的前缀函数 pi[i] 表示模式串到位置 i 的前缀中，最长相等的真前缀和后缀长度。匹配失败时，不把文本指针退回起点，而是将已匹配长度 j 回退到 pi[j-1]，继续尝试更短但仍可能匹配的前缀。

模式 ababaca 的前缀函数为 [0,0,1,2,3,0,1]。处理字符 c 时，不能继续延长 ababa，于是沿更短相等前后缀回退。总预处理 O(m)，匹配 O(n)，辅助空间 O(m)。不能把失败跳转写成每次 j-- 后重扫文本，这会丢掉线性时间优势。练习 [LC 28](https://leetcode.com/problems/find-the-index-of-the-first-occurrence-in-a-string/)。

## 快速选择：只分区，不完整排序

选定枢轴后，将数组分成较小、相等、较大区域，根据目标秩只进入必要的一侧。随机化普通快速选择的期望时间为 O(n)，最坏仍可能 O(n²)；重复值多时，三路分区比仅分两侧更容易避免大量无效工作。

手写前说明是否可以修改输入，以及 k 是从小到大还是从大到小。固定内存流式 Top K 则更适合容量为 K 的堆，因为快速选择需要持有待分区数据。练习 [LC 215](./05-stack-heap.md#lc-215)。

## 最短路选型：BFS、0-1 BFS 与 Dijkstra

| 边权模型 | 常用算法 | 核心条件 |
| --- | --- | --- |
| 等权边 | BFS | 按层扩展等价于按距离扩展 |
| 权重仅为 0 或 1 | 0-1 BFS | 0 权边推队首，1 权边推队尾 |
| 非负权 | Dijkstra | 每次取当前未确定的最小距离节点 |
| 含负权 | 按场景用 Bellman-Ford 等 | 还需检查可达负环，最短路可能无有限值 |

Dijkstra 的关键不是“用了优先队列”，而是非负边使已经选出的最小距离不会被后续绕路改善。用堆的邻接表实现常按 O((V+E) log V) 描述；采用允许重复入堆的懒更新实现时，还应说明过期条目跳过规则以及堆空间与 E 的关系。

例：A→B 权重 10，A→C 权重 1，C→B 权重 1。最少边路径是 A→B，但最低代价路径是 A→C→B，总代价 2，普通 BFS 不适用。练习 [LC 743](https://leetcode.com/problems/network-delay-time/)。

## 大数据题：先说精确性与内存约束

**海量 Top K：** 内存内可使用大小 K 的堆；多路已排序流可以做堆归并。若跨分片比较分数，需确认各分片使用一致的可比较排序定义；统计频次则通常必须先按键聚合，不能简单把各分片局部高频键当作全局完整结果。

**数据流均匀抽样：** 容量 K 的蓄水池先收下前 K 个元素。此后第 i 个元素到达（i > K）时，以 K/i 的概率让其进入并等概率替换一个已有位置。归纳可证明此时每个已见元素被保留概率为 K/i；这不是维护最大 K 个，也不是按权重采样。

**去重与成员判断：** 哈希集合可做精确成员判断但占内存。标准布隆过滤器以误报换空间，在正确插入且不删除的模型下不应漏掉已插入元素，但“判定可能存在”不等于已经精确去重。需要零误差时仍要真实存储校验。

**外部排序：** 当数据不能一次放入内存时，按内存大小生成有序段，再进行多路归并，重点从 CPU 比较次数扩展到磁盘吞吐、归并路数、临时空间和失败恢复。

## 后端工程面试如何衔接

将算法模型与实际需求分开：算法中的固定容量不等于生产内存上限；单线程数据结构不等于并发安全组件；平均复杂度不等于尾延迟保证；离线最优不等于流式可增量维护。答完核心手写，再说明输入规模、更新方式、资源预算、精确性与故障恢复，才是有意义的工程延伸。
