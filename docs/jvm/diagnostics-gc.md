## 17. 线上 CPU 飙高怎么排查？

**面试官意图：**考察系统化排障。

**高分回答：**先确认范围和时间，检查流量、发布和依赖；用 top 定位进程/线程，线程转储映射热点栈，结合 JFR、GC、锁和系统调用判断 CPU 计算、死循环、序列化或自旋。修复前先限流或降级控制影响。

**连续追问：**如果是 GC 导致？

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：如果是 GC 导致？

**标准答法：**先看 GC 日志/JFR：分配速率、暂停、老年代占用和回收效果，区分高分配、内存泄漏和堆配置不当。止血可限流/回滚；修复对象生命周期、批量大小或缓存，再调 GC 参数，不能先盲目加堆。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

**答题风险：**不要直接重启结束。

**体现资深水平：**先止血、再定位、再验证。

## 18. 内存持续增长但 GC 后不下降怎么办？

**面试官意图：**考察泄漏排查。

**高分回答：**区分堆、直接内存、线程和缓存。观察 GC 后老年代基线，抓取多个 Heap Dump 比较对象增长和 GC Roots；检查无界缓存、ThreadLocal、监听器和大集合。生产操作要控制 Dump 开销。

**连续追问：**直接内存如何看？

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：直接内存如何看？

**标准答法：**使用 NMT（需启动参数）、jcmd VM.native_memory、进程 RSS 与堆差值、direct buffer pool 指标和线程数分析；检查 Netty/NIO DirectByteBuffer、mmap 和本地库。直接内存 OOM 不一定出现在 Heap Dump。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

**答题风险：**不要只说调大 Xmx。

**体现资深水平：**用时间序列证据而不是单点快照。

## 排障闭环

1. 先确认影响范围、开始时间、发布/流量/依赖变化并止血。
2. 用系统、JVM、线程、GC 和业务指标缩小范围。
3. 用 JFR、线程转储、GC 日志、Heap Dump 或 NMT 建立证据。
4. 区分高分配、泄漏、锁竞争、计算热点、直接内存和线程数量问题。
5. 修复后在同类负载下验证，并补告警、容量基线与回归测试。
