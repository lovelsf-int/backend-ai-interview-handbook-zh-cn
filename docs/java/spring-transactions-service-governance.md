# Spring 事务与服务治理

## Spring、事务与服务治理

**Q @Transactional 为什么会失效？**

> **面试官意图：**资深 Java 必问。
>
> **高分要点：**代理、自调用、非 public、异常被吞、异常类型、异步线程、未被 Spring 管理、事务管理器错误。
>
> **连续追问：**REQUIRES_NEW 风险；事务传播；异步方法继承事务吗。

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：REQUIRES_NEW 风险？

**标准答法：**REQUIRES_NEW 会挂起外层事务并占用额外连接；并发高时可能导致连接池耗尽，内层提交后外层回滚还会产生业务不一致。只用于真正独立且可接受先提交的操作，如必要审计，并控制范围。

Q2：事务传播？

**标准答法：**说明 REQUIRED、REQUIRES_NEW、NESTED 等核心传播即可，重点结合业务：默认加入现有事务，独立事务的提交语义和补偿要明确。不要只背七个枚举。

Q3：异步方法继承事务吗？

**标准答法：**不会。Spring 传统事务通常绑定当前线程，新启动的异步线程不继承；应在异步方法内开启自己的事务或通过可靠消息传递状态。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

> **回答风险：**只回答“同类调用”。

**Q 事务方法中发送 Kafka 消息有什么问题？**

> **面试官意图：**考察 DB 与消息一致性。
>
> **高分要点：**DB 提交和消息发送不是同一原子操作；使用 Outbox、本地消息表或事务消息，并要求下游幂等。
>
> **连续追问：**消息发出后事务回滚；Outbox 重复。

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：消息发出后事务回滚？

**标准答法：**若先发消息后数据库回滚，下游可能看到不存在的业务事实。因此业务数据与 Outbox 同事务，发布器只发送已提交事件；或者使用支持的事务消息，但仍需端到端幂等。

Q2：Outbox 重复？

**标准答法：**Outbox 本身允许重复：消息发送成功但状态更新失败会再次发。稳定 event_id 和下游幂等吸收重复，发布状态更新不能放在发送前。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

> **回答风险：**在 finally 中发消息就认为可靠。

**Q 如何设计统一的超时、重试、熔断和降级？**

> **面试官意图：**考察服务治理。
>
> **高分要点：**区分连接/读取/总超时；仅重试幂等和可恢复错误；指数退避；熔断保护下游；降级有业务语义；全链路指标。
>
> **连续追问：**重试放大；超时层层叠加。

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：重试放大？

**标准答法：**每层独立重试会形成乘法放大，例如网关 3 次×服务 3 次×SDK 3 次。选择一个主要重试层，设置总重试预算、指数退避和幂等；限流/过载时减少而不是增加重试。

Q2：超时层层叠加？

**标准答法：**从端到端 SLA 反推总预算，再分配连接、读取和处理超时；外层需留出返回与清理时间。避免每层都设相同 30 秒，导致用户早已超时而后台仍工作。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

> **回答风险：**所有异常统一重试三次。

## 19. 如何设计统一幂等组件？

**面试官意图：**考察抽象能力。

**高分回答：**先区分请求幂等、消息幂等和业务状态机。组件可以提供幂等键解析、唯一记录、处理中/成功/失败状态、结果缓存和过期策略，但业务副作用仍需事务或状态机。不能用一个 Redis 锁宣称解决所有幂等。

**连续追问：**处理中超时怎么办？

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：处理中超时怎么办？

**标准答法：**处理中记录 lease_owner、lease_expire_at 和 heartbeat；超时扫描后先判断是否可能有外部副作用。无副作用可抢占重试；未知状态先查询/对账，超过次数进人工。客户端重复请求读取原处理状态。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

**答题风险：**不要过度平台化。

**体现资深水平：**抽象公共机制，保留业务语义。

## 20. 如何设计可观测性？

**面试官意图：**考察生产责任。

**高分回答：**至少覆盖 Trace、Metric、Log 和审计。Agent 链路要记录 task_id、alert_id、model/prompt/knowledge 版本、工具调用、Token、延迟和状态；支付链路记录 order_id、channel_txn_id、状态迁移和回调。指标设置 SLO、错误率、P95/P99、积压和降级比例。敏感字段脱敏。

**连续追问：**日志能否记录 Prompt？

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：日志能否记录 Prompt？

**标准答法：**不能默认记录完整 Prompt，因为可能含告警原文、个人信息、密钥或攻击载荷。记录 prompt_version、模板哈希、Token、脱敏摘要和必要证据 ID；只有受控安全存储在审批和保留期内保存完整内容。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

**答题风险：**不要只说接入 ELK。

**体现资深水平：**可观测性必须支持回答业务问题和故障问题。

## 21. 服务如何优雅停机？

**面试官意图：**考察发布稳定性。

**高分回答：**停止接收新请求、从注册中心摘除、等待进行中请求和消息完成、提交 Offset 或释放租约、关闭线程池和连接池，并设置最大等待时间。Agent 长任务可能需要持久化状态后转移，而不是强行等待。

**连续追问：**K8s preStop？

追问标准答案（可直接口述，方括号内容须替换为真实信息）

Q1：K8s preStop？

**标准答法：**preStop 先让实例从流量/消费组摘除，再等待短暂 drain；terminationGracePeriod 要覆盖最大可接受请求。长 Agent 任务应先持久化检查点和释放租约，由其他实例恢复，而不是无限延长关机。Kafka Consumer 在退出前停止拉取、完成/中止处理并安全关闭。

使用提醒：先理解逻辑，再替换成自己的真实参数和项目事实；不要逐字背诵。

**答题风险：**不要只调用 shutdown。

**体现资深水平：**根据任务类型定义可迁移性。
