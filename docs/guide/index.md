# 使用指南：先读这一页 {#使用指南}

不需要从头读完整个仓库。今天只选一个问题：先闭卷回答，再补不会的部分；能解释机制、失败边界和验证方法，就跳过正文。

## 推荐入口

1. **不知道先读什么**：[诊断与短路线](./learning-path.md)，一次只读 1–2 篇。
2. **补一个知识点**：[知识主入口](./topic-map.md)，同一知识点只选一份主读。
3. **准备讲自己的项目**：[项目案例](./projects.md)，查业务约束、个人职责和真实证据。
4. **检验会不会**：[练习与复盘](./practice.md)，先答题，错了再回主入口。
5. **查旧说法或材料来源**：[历史与来源](./archive.md)，不放进日常必读队列。

## 如何判断内容可信度

页面的 `baseline` 决定适用版本；`verified` 是既有校准状态，不能代替运行验证；`reviewing` 表示仍有待核验项；`legacy` 只解释历史行为。项目数字要分清事实、估算、目标与教学假设。

AI Agent 工程章节是生产语义的主入口；[AI 学习资料](../ai-study/) 是按需补基础的许可快照，两套不用从头各读一遍。涉及版本冲突，先看对应专题和[版本边界](../ai-study/version-notes.md)。

## 面试使用方式

每次 25 分钟：3 分钟闭卷诊断 → 15 分钟只读卡住的一节 → 7 分钟复述或写一个反例。练习安排可按自己的精力调整。

答题只需四段：结论 → 关键机制 → 项目条件 → 异常与取舍。读完还说不清，就记录一个具体问题，下次只补这个问题。

## 不必做的事

- 不把专题正文、综合手册、题库答案和历史复盘当四套新知识反复读。
- 不把旧面试表现当成今天能力判断，也不把没填的项目证据当成知识空白。
- 不把全部文章数量当成学习进度。今天能说明一个失败边界，比又浏览十篇更有用。
