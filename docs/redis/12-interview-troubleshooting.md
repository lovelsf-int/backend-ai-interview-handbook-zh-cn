# Redis 面试速答与故障排查

## 90 秒回答主线

先说明 Redis 的内存访问、事件循环与数据结构，再进入持久化、高可用、分片和缓存一致性。回答必须包含阻塞点、失败路径、版本差异和监控证据。

## 高频排障顺序

1. 确认现象：延迟、错误率、超时、内存、连接、复制或数据一致性。
2. 检查实例资源、事件循环延迟、慢日志、客户端连接和网络。
3. 检查 BigKey/HotKey、过期风暴、AOF/RDB、主从复制和故障转移。
4. 检查客户端重试、连接池、超时和缓存降级是否放大故障。
5. 修复后补容量基线、告警、演练和回滚验证。

## 必须纠正的说法

- “Redis 完全单线程”缺少版本和执行路径边界。
- “事务或 Lua 出错会自动回滚”不成立。
- “Redis 锁设置过期时间就绝对安全”不成立。
- “某种内部编码永远不变”不成立。
- “使用 Sentinel/Cluster 就自动获得强一致”不成立。
