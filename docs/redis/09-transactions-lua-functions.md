# 事务、Lua 与 Functions

> 核心边界：Redis 事务不会像关系数据库一样在运行时错误后自动回滚；Lua 的原子执行也不代表脚本错误会恢复已经产生的副作用。

## 第十章 Redis 事务机制（P7高频漏考点）

### 10.1 Redis 事务核心原理

Redis 事务三指令：**MULTI / EXEC / DISCARD**，Watch 为乐观锁辅助。

Redis 事务本质：**命令批量打包、一次性串行执行**。

执行三阶段：

**开启事务(MULTI)**：客户端进入事务状态，后续命令不执行、入队缓存

**命令入队**：批量写入命令队列

**执行事务(EXEC)**：主线程一次性、串行、原子执行所有队列命令

### 10.2 Redis 事务三大特性（面试必背）

**1、单独隔离性**

事务执行过程中，其他客户端命令**绝对无法插队**，保证批量命令连续执行。

**2、无回滚机制（最大坑点）**

**Redis 事务不支持事务回滚**！

语法错误：整体事务不执行；

运行时逻辑错误（比如对String执行List操作）：**错误命令报错，正确命令照常执行**，不会回滚。

**3、最终原子性（近似原子）**

不是数据库严格原子性（失败回滚），是**要么全部执行、要么全部不执行**（仅针对正常情况）。

### 10.3 Watch 乐观锁机制（CAS）

**作用**：解决事务期间数据被其他线程修改的并发问题。

原理：

Watch 监听若干 Key

若事务提交前 Key 被修改，**事务直接放弃执行**

无版本号，靠服务端数据变动检测

**缺陷**：仅支持乐观锁，不适合高并发争抢场景。

### 10.4 Redis 事务为什么不支持回滚？（P7经典面试题）

官方设计理由（背诵版）：

Redis 追求**极致高性能、简单轻量化**；

事务错误基本都是**编程语法错误、命令误用**，属于开发Bug，生产应该避免；

增加回滚日志会大幅增加内存、代码复杂度、降低吞吐；

业务层可自行规避，无需Redis底层兜底。

### 10.5 Redis Cluster 集群事务致命问题

**集群下不支持跨哈希槽事务**

原因：Redis Cluster 每个槽位是独立节点，无法跨节点统一事务协调、无法全局加锁。

**解决方案**：

**HashTag** 强制多个Key落到同一个哈希槽，支持事务/批量操作

复杂分布式事务使用 Lua / Redisson 分布式锁兜底

### 10.6 Redis事务 vs Lua脚本（面试高频对比）

**事务**：多条命令打包，不支持逻辑判断、不支持回滚、原子弱

**Lua脚本**：服务端一次性执行、支持判断循环、**真正原子**、生产替代事务

**生产结论**：业务原子需求一律用 Lua，不用原生事务。

### 10.8 Lua 脚本完整考点（面试必问：Lua 是什么？优势？原理？）

#### 10.8.1 Lua 脚本是什么

Lua 是一种**轻量、嵌入式脚本语言**，Redis 原生内置 Lua 解释器，支持客户端将**多条 Redis 命令 + 业务逻辑**封装成一段脚本，一次性提交给 Redis 服务端执行。

简单理解：**Lua = Redis 服务端批量原子编程能力**。

#### 10.8.2 Lua 脚本核心执行特性（面试核心）

**服务端原子执行**：整个 Lua 脚本在 Redis 主线程中**独占执行、不可插队、不被打断**，天然具备真正原子性，远超原生事务。

**网络开销极低**：多次命令合并为一次网络 IO，极大降低客户端与服务端的往返耗时。

**支持逻辑运算**：原生事务只能无脑批量执行，Lua 支持 **if/else、循环、变量、判断返回值**，可以实现复杂业务原子逻辑。

**脚本可缓存复用**：通过 SHA1 摘要缓存脚本，无需每次传完整代码，性能更高。

#### 10.8.3 为什么 Lua 比 Redis 原生事务更强？

原生事务：**弱事务、不回滚、不支持逻辑判断、运行报错数据脏写**；

Lua 脚本：**真原子、整体成功整体失败、支持业务逻辑、无中间脏数据**。

#### 10.8.4 Lua 脚本生产使用规范（P7架构考点）

**禁止死循环、禁止超长耗时逻辑**：Lua 阻塞主线程，超时会导致 Redis 整体卡死；

**脚本尽量短小**：只做 Redis 读写判断，不做业务计算、RPC、DB 查询；

**集群环境必须保证单槽 Key**：Lua 脚本所有操作 Key 必须落在同一个哈希槽（HashTag），否则执行报错；

**线上禁止裸写脚本**：统一管理、预加载、SHA 缓存，避免重复编译。

#### 10.8.5 Lua 典型落地场景

分布式锁加解锁原子逻辑（Redisson 底层全是 Lua）

库存扣减、防超卖原子操作

限流计数器原子更新

多 Key 批量原子读写、条件更新

### 10.7 面试终极总结（可直接口述）

Redis事务是**弱事务**，无回滚、仅命令打包串行执行；单机可用，集群跨槽失效；简单场景可用，复杂原子场景一律用Lua脚本或分布式锁解决。
