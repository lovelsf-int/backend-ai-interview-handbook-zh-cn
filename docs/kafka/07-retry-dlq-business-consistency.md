# 重试、死信与业务一致性

## 第八章：重试、死信与业务一致性

### 8.1 错误分类

- 可瞬时恢复：网络抖动、下游短暂超时、限流；有限重试。

- 可延迟恢复：第三方长时间不可用；进入延迟重试 Topic。

- 数据问题：Schema 不兼容、字段非法；进入死信并告警。

- 业务拒绝：余额不足、状态冲突；记录业务结果，不应无限技术重试。

- 不可恢复：权限、认证、配置错误；快速失败并停止实例或人工介入。

### 8.2 重试 Topic 设计

- 原 Topic 消费失败后写入带 retry_count、next_retry_time、原 Topic/Partition/Offset、错误码的重试事件。

- 按不同延迟级别设计 Topic，或使用调度服务控制重投。

- 设置最大次数和总时间预算。

- 最终失败进入 DLQ，并提供查询、修复、重放和审计工具。

- 重试消息必须保留稳定 event_id，下游仍做幂等。

### 8.3 顺序业务的重试

若同一业务 Key 必须严格顺序，单条失败后直接把后续消息继续处理可能造成状态倒置。可选方案：

- 暂停该分区，修复后继续，顺序强但影响同分区其他 Key。

- Key 级队列或状态机隔离失败 Key，实现更细粒度阻塞。

- 允许乱序但用业务版本号拒绝旧事件。

要根据影响面和 SLA 选择，不存在通用最优方案。
